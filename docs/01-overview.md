# 1. カスタム推奨事項の概要

## 1.1 何を作るのか

KQL ベースのカスタム推奨事項は、Defender for Cloud が保持する資産メタデータを評価し、各資産を `HEALTHY` または `UNHEALTHY` に分類します。組織固有の基準や、AWS/GCP のベストプラクティスを Defender for Cloud の統一された推奨事項画面に追加できます。

作成処理は次の流れです。

1. AWS/GCP コネクタが資産情報を収集する。
2. `RawEntityMetadata` に対して KQL を実行する。
3. クエリが資産識別情報と `HealthStatus` を返す。
4. Defender for Cloud が不健全な資産、重大度、修復手順を推奨事項として表示する。

## 1.2 前提となる機能と権限

- Defender CSPM プラン
- AWS/GCP の環境コネクタ
- 対象管理グループ、サブスクリプション、またはコネクタを扱える権限
- カスタム標準と推奨事項の作成には Owner または Security Admin 相当の権限

ポータルの画面、利用可能なスコープ、必要なロールは更新されることがあります。実施時点の Microsoft Learn を確認してください。

## 1.3 2種類の KQL を区別する

| 目的 | 入力 | 実行場所の例 |
|---|---|---|
| カスタム推奨事項の健全性判定 | `RawEntityMetadata` | Defender for Cloud のカスタム推奨事項作成画面 |
| 作成済み評価結果の集計 | `securityresources` | Azure Resource Graph Explorer |

`securityresources` の `microsoft.security/assessments` は評価結果です。AWS/GCP 資産の設定を直接判定するクエリの入力として置き換えることはできません。

## 1.4 設計上の責任

ベンダーのコントロールと、コネクタが収集するフィールドは同じものではありません。例えば「S3 の公開アクセスを禁止する」という要件があっても、バケット本体、ACL、バケットポリシー、アカウントレベル設定が別資産として収集される場合があります。

カスタム推奨事項を作成する担当者は次を決定します。

- どの資産型を評価対象とするか
- どのプロパティがコントロールの証拠になるか
- プロパティ欠損時に評価対象外とするか、別の収集経路を用意するか
- 例外をタグ、アカウント、プロジェクト、リージョンなどでどう表現するか
- 重大度、修復手順、オーナーをどう定義するか

## 1.5 推奨ライフサイクル

1. 探索: 型と JSON パスを列挙する。
2. 仮説: ベストプラクティスを1つの真偽条件に変換する。
3. 検証: 正常資産と意図的に不正設定にした資産で結果を比較する。
4. 登録: 小さいスコープでカスタム推奨事項を公開する。
5. 監視: 対象件数、欠損率、誤検知を確認する。
6. 展開: 例外と修復手順を整備して対象スコープを広げる。
